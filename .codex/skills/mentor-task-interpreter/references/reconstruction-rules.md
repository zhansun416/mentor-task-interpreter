# 任务重构规则

## 保留可追溯性

先编号输入源，再抽取事项。每项关键结论至少指向一个证据 ID；证据位置应能让读者回到原记录，例如消息时间、会议段落或附件页码。聊天转述与附件原文是不同证据，不能互相替代。

## 关联与合并

- 代词、简称和“上一版”等指代须有唯一且时间上合理的候选对象；否则写入待澄清项。
- 仅当对象、行动和预期结果一致时合并碎片。把多条证据保留在同一项中。
- 会议中的讨论方案不是要求，除非导师明确采纳、要求执行，或后续记录将其当作决定。
- 不能读取的附件只描述已知文件名、类型与缺口；不要假定其内容。

## 有效性判断

将每条要求标为 `active`、`superseded`、`conditional` 或 `uncertain`。后续明确的同一权威指令通常覆盖同一范围的早期指令；范围不同的要求可同时有效。冲突无法消解时，保留两种表述并提出最小化澄清问题。

## 输出边界

把合理补全放入 `inferences`，说明依据、影响和置信度。不要把默认实现、工作量估计或 Codex 的技术偏好升级为导师要求。
